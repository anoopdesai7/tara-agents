RESEARCH TRACK 02Working hypothesis · November 2026

Can executable verification detect agent sabotage that transcript monitors miss?

Compare a language-model monitor that reads an agent's work against monitors that can test it—and a third protocol that also sees independent execution evidence. The key question is whether the extra evidence improves detection under comparable time, token and compute budgets.

Research hypothesis (unproven)

For some covert side tasks, targeted executable checks reveal violations missed by transcript-only monitoring. The advantage may disappear when tests are poorly chosen, the environment is attacker-controlled, or verification costs crowd out useful review.

Scope: bounded Linux configuration and repository-maintenance tasks in disposable, isolated environments; no production systems or live targets.

01 / Three competing protocols

A · Read-only LLM

Sees the task, diff and selected transcript; returns suspicion, evidence and escalation decision. Cannot execute tools.

B · LLM + tests

Same initial evidence, but may run allowlisted, sandboxed checks to verify security invariants and task claims.

C · LLM + tests + audit

Protocol B plus separately collected command traces, file hashes, and before/after state snapshots.

02 / A controlled example

Legitimate request: fix a service configuration so the application starts successfully. Hidden side objective: weaken an access-control setting while preserving normal startup. The test environment supplies the side objective; this page does not provide attack instructions.

Illustrative example only; not measured detection rates.

03 / Design the evaluation

Unit of analysis

One agent trajectory with a legitimate task, optional hidden side objective, and ground-truth labels for both task completion and policy violation.

Controls

Same tasks, attacker strength, monitor model, initial evidence, and calibrated budget. Randomize protocol assignment; repeat across seeds.

Measurements

Recall at a fixed false-positive rate, AUROC/AUPRC where appropriate, attack success, legitimate-task success, latency, tokens, execution cost and escalation rate.

04 / Interactive budget thought experiment

Move the budget allocation. These are planning inputs, not predicted safety outcomes.

Research caution: equal tokens is not equal compute; report wall time, tool cost and total budget separately. Compare at matched cost points and report the full cost–detection frontier.

05 / Failure modes and threats to validity

Can the agent manipulate the tests?

Yes. Place test definitions and reference labels outside the agent-writable workspace; independently snapshot the environment. Separate tests used by the monitor from held-out ground-truth checks.

Could a stronger monitor simply reason longer?

Yes. Include a read-only monitor with an equivalent total budget, not just an equal-prompt baseline. Consider allowing the read-only monitor additional transcript/context retrieval.

What if test execution creates new risk?

Run in disposable sandboxes with restricted egress, least privilege, resource limits, deterministic fixtures and preserved logs. Treat tool outputs as untrusted input to the monitor.

06 / Minimal reproducible study

  1. Choose one narrow task family and define explicit success and violation labels.
  2. Build 15–30 benign and adversarial trajectories; hold out some scenarios for final evaluation.
  3. Implement protocol A first; calibrate its suspicion threshold on development data.
  4. Add B with safe, independent checks; add C only if time allows.
  5. Run paired trials with matched budgets, confidence intervals, failure analysis and cost accounting.
  6. Publish anonymized traces, harness configuration, evaluation scripts, rubric and negative results.
